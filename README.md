# Knowledge-Graph-Constrained Generative Probabilistic Planning (KG-GPP)

Reproducibility package for:

**Trustworthy AI and Risk-Aware Planning for Global Supply Chains: A Probabilistic Framework with Knowledge Graph Constraints**

## Implementation Scope

This repository implements the empirical KG-GPP benchmark used in the manuscript:
a one-step model-based expected-objective action selector operating over a
knowledge-graph-constrained feasible action set, together with the
reinforcement-learning and heuristic comparators, robustness experiments, selected figure generation, and reproducibility outputs.

The general sequential KG-constrained partially observable Markov decision process
(POMDP) presented in the manuscript provides the broader theoretical formulation.
The repository therefore reproduces the empirical implementation evaluated in the
paper rather than a general-purpose solver for the full sequential POMDP
formulation.

## 1. Clone the Repository

```bash
git clone https://github.com/malka-nisha/Trustworthy-AI-4Global-Supply-Chains.git
cd Trustworthy-AI-4Global-Supply-Chains
```

## 2. Install Dependencies

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-core.txt
```

The complete environment reported for the manuscript is listed in
`requirements-manuscript.txt`.

## 3. Download and Place the DataCo Dataset

Download the public DataCo Supply Chain dataset from:

<https://data.mendeley.com/datasets/8gx2fvg2k6/3>

Place the downloaded file here:

```text
project_root/
└── data/
    └── DataCoSupplyChainDataset.csv
```

The raw dataset is not committed to this repository. DataCo does not contain
ground-truth labels for ideological risk, trust, or supplier bias; trust and
disparity are operational proxies defined in
`results/dataco_proxy_definitions.csv`.

## 4. Run the Experiments

From the repository root, run the benchmark, robustness, and complexity analyses:

```bash
python code/run_r3_experiments.py \
  --data-path data/DataCoSupplyChainDataset.csv \
  --output-dir .
```

Aggregate outputs are written to `results/`, and run configuration is written to
`logs/run_metadata.json`. Individual computational outcomes are provided in
`results/instance_results.csv.gz`. The file contains 1,225,000 evaluation records
covering 25,000 held-out instances across the retained policy-scenario
evaluations, comprising nine benchmark policies and eight robustness scenarios.
Each record includes the instance identifier, policy, scenario, selected action,
estimated risk, critical-outcome indicator, cost, residual trust loss, disparity
proxy, and constraint-violation status. These records provide the machine-readable
evidence underlying the aggregate benchmark and robustness results reported in the
manuscript.

The aggregate files used to construct the reported computational summaries are
retained in `results/` so that the results can be traced to saved outputs. The
figure files used in the manuscript are retained in `figures/`. The runner
regenerates the bounded Bayesian risk diagnostic (`Fig_Bayesian_Risk_Inference.png`);
the other figure files are supplied rendered outputs from the DataCo/digital-twin
analysis and are not generated by the benchmark runner.

## 5. Reproducibility Configuration

```text
Random seed:       20260602
Training rows:     60,000
Evaluation rows:   25,000
Training epochs:   160
Batch size:        2,048
Learning rate:     0.012
```

These values can be overridden using:

```bash
python code/run_r3_experiments.py --help
```

The experiment is simulator-based and uses the documented DataCo preprocessing,
digital-twin assumptions, and operational proxy definitions.

The code is organized into focused modules: `data_state.py` constructs the
DataCo state and KG feasibility mask, `simulation.py` contains digital-twin
outcome logic, `policies.py` implements the heuristic, RL, and KG-GPP policies,
and `experiment_runner.py` coordinates the benchmark and robustness runs.
`run_r3_experiments.py` is the command-line entry point.

## 6. Inspect Individual Results

```python
import pandas as pd

results = pd.read_csv("results/instance_results.csv.gz")
print(results.head())
```

### Individual-result schema

`results/instance_results.csv.gz` contains the retained evaluation-level
computational outputs used to construct the reported aggregate results.

The principal fields are:

- `InstanceID` — held-out evaluation instance identifier;
- `Policy` — evaluated decision policy;
- `Scenario` — benchmark or perturbation scenario;
- `action` — selected intervention/action;
- `risk` — estimated failure risk;
- `critical` — indicator used in critical-failure-rate estimation;
- `cost` — normalized operational cost;
- `trust_loss` — residual trust-loss measure;
- `bias_after` — residual operational disparity/bias proxy; and
- `constraint_violation` — feasibility/constraint-violation indicator.

The file contains 1,225,000 evaluation records covering 25,000 held-out
instances across the retained policy-scenario evaluations, comprising nine
benchmark policies and eight robustness scenarios.

The files in `results/` provide the machine-readable outputs needed to verify the
computational results reported in the manuscript.
